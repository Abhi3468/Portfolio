Todo — task manager

A full-stack Django task-management application that combines a DRF API, asynchronous browser interactions, authentication workflows, MySQL persistence, and downloadable reports.

The problem

A task list is simple until it needs a responsive user experience, isolated user accounts, reliable CRUD behaviour, and a way to export useful information. This project was used to practise those connected full-stack concerns.

  • Let authenticated users create, update, complete, and remove their own tasks.
  • Use a REST API and browser fetch() calls so common actions update without a full page reload.
  • Provide custom registration, login, and password-recovery flows.
  • Generate a PDF task-list report from server-side data.

Architecture

Interactive UI

HTML, CSS, and vanilla JavaScript handle responsive interactions and API requests.

Django + DRF

Django supplies authentication and pages; DRF exposes task operations as structured endpoints.

MySQL + reports

MySQL persists task and user data, while ReportLab creates downloadable PDF exports.

Key engineering decisions

API-driven interactions

JavaScript uses asynchronous requests for common task changes, keeping the UI responsive while retaining Django on the backend.

Account boundaries

Authentication flows and per-user task data make ownership an explicit part of every task operation.

Useful exports

PDF generation turns the same stored task data into a portable report without duplicating it in the client.

Validation and next steps

The repository documents local setup with Django and MySQL. The next technical iteration is to add a reproducible containerised development environment and CI checks, then document those results in the repository before adding them to this case study.

This case study describes the public implementation today. Docker Compose, Nginx, PostgreSQL, health checks, and production-deployment claims are intentionally excluded until they are implemented and tested.

What I learned

Good full-stack work is about the boundary between interface and backend: a clear API, user-owned data, predictable failure handling, and features that solve a real user need rather than a one-screen demo.
